# XML parsing scope for feeds

MoonFeed's `src/xmlmini` package is an internal event reader for RSS and Atom. It is not a general-purpose XML processor, validator, or serializer.

It handles the XML 1.0 syntax used by the feed parsers: element and attribute syntax, quoted values, predefined and numeric character references, CDATA, comments, processing instructions, namespace expansion, line-end normalization, and document checks. The shared Reader, and therefore NamespaceReader, requires exactly one document element. The open-tag stack and document-element-seen state distinguish the prolog, root content and post-root Misc; root-external text, character/entity references (even encoded whitespace), CDATA and additional roots are rejected. Legal literal XML whitespace, comments and processing instructions are consumed and validated before or after the root. EOF without a root is an error. RSS/Atom retain their builder checks as a backstop.

Consumers validating a complete document must drain events through Eof: reading only an opening/root event cannot establish whether the remaining document is well formed. The format detector intentionally reads only the prefix; callers use the parser for full validation. This reader is not a fragment parser. The formal feedback and direct Reader/NamespaceReader tests are documented in [RSS20_FORMAL_ACCEPTANCE_FIX](RSS20_FORMAL_ACCEPTANCE_FIX.md); this XML document-layer correction is shared by RSS and Atom, not an RSS-only string filter.

For an internal `DOCTYPE` subset, the reader expands declared internal general entities that produce text, applies internal `ATTLIST` default values, and performs XML attribute whitespace normalization for declared CDATA and tokenized types. Entity replacement is bounded to 32 nested references and 1 MiB per decoded value. A declared entity whose replacement contains markup is rejected when used because the event reader does not inject replacement markup into the XML event stream.

This is deliberately not complete DTD processing. Parameter-entity references, external subsets, external general entities, DTD content-model/type validity checks, and defaults declared externally are not processed. External identifiers are parsed but never dereferenced. The reader does not perform XML Schema validation. Callers pass decoded text; byte-level encoding detection and conversion are outside this API. These limits mean MoonFeed still does not consume every legal XML 1.0 Atom serialization; see the [Atom compatibility matrix](ATOM_RFC4287_COMPLIANCE.md).
