# XML parsing scope for feeds

MoonFeed's `src/xmlmini` package is an internal event reader for RSS and Atom. It is not a general-purpose XML processor, validator, or serializer.

Maintenance/0.3.1 adds a leading decoded BOM, strict CLI UTF-8 byte decoding, checks across the entire consumed DOCTYPE, PUBLIC/ATTLIST/ELEMENT/NOTATION lexical grammar, and correct EntityValue character-reference timing. Attribute normalization distinguishes character references directly in an attribute from whitespace introduced by an internal entity; tokenized normalization collapses only #x20. Valid Unicode text is retained, including a genuinely encoded U+FFFD; malformed byte sequences fail before parsing. The String API assumes already-decoded text, and the CLI does not transcode UTF-16 or arbitrary encodings.

Nonvalidating does not mean ignoring the internal subset's well-formedness. These fixes improve that boundary without implementing markup-producing entity input frames or unread-parameter-entity processing. Those remain real coverage gaps, separately from the deliberate no-external-fetch and expansion-limit policy; see [the audited requirements](RFC4287_REMAINING_GAPS_AUDIT.md). DTD instance validity remains unchecked.

It handles the XML 1.0 syntax used by the feed parsers: element and attribute syntax, quoted values, predefined and numeric character references, CDATA, comments, processing instructions, namespace expansion, line-end normalization, and document checks. The shared Reader, and therefore NamespaceReader, requires exactly one document element. The open-tag stack and document-element-seen state distinguish the prolog, root content and post-root Misc; root-external text, character/entity references (even encoded whitespace), CDATA and additional roots are rejected. Legal literal XML whitespace, comments and processing instructions are consumed and validated before or after the root. EOF without a root is an error. RSS/Atom retain their builder checks as a backstop.

Consumers validating a complete document must drain events through Eof: reading only an opening/root event cannot establish whether the remaining document is well formed. The format detector intentionally reads only the prefix; callers use the parser for full validation. This reader is not a fragment parser. The formal feedback and direct Reader/NamespaceReader tests are documented in [RSS20_FORMAL_ACCEPTANCE_FIX](RSS20_FORMAL_ACCEPTANCE_FIX.md); this XML document-layer correction is shared by RSS and Atom, not an RSS-only string filter.

For an internal `DOCTYPE` subset, the reader expands declared internal general entities that produce text, applies internal `ATTLIST` default values, and performs XML attribute whitespace normalization for declared CDATA and tokenized types. Maintenance expansion uses explicit frames and a shared lifetime budget across attributes, defaults and text: 32 entity levels, 65,536 references (including predefined/numeric references), 16,777,216 work units, and 8,388,608 produced UTF-8 bytes. Empty expansions consume references/work before processing. Each decoded value retains the earlier 1,048,576-character ceiling; this is not a 1 MiB byte limit. CDATA also consumes the shared output budget. Input is capped at 16,777,216 UTF-8 bytes, including a BOM and original line endings; element nesting is capped at 256 (DTD content-model nesting remains separately bounded). A limit failure is sticky and uses the existing typed XML error. See [the security fix and exact accounting](SECURITY_0.3.1_FIX.md).

Internal entity declarations are checked by an iterative dependency graph, without expanding an exponential tree. Forbidden parameter-entity NDATA syntax, applicable undeclared references, cycles and direct/indirect default references preceding their declarations are rejected, even for unused attribute declarations. Legal forward references between general entities and first-declaration binding remain supported. For an unread external subset, declaration completeness is not assumed unless standalone=yes; using an unresolved or external entity still fails clearly. Parsed external entities and unparsed NDATA entities have distinct diagnostics; no resources are fetched. Markup-producing general entities remain explicitly unsupported, rather than injected into the event stream.

This is deliberately not complete DTD processing. Parameter-entity references, external subsets, external general entities, DTD content-model/type validity checks, and defaults declared externally are not processed. External identifiers are parsed but never dereferenced. The reader does not perform XML Schema validation. Callers pass decoded text; byte-level encoding detection and conversion are outside this API. These limits mean MoonFeed still does not consume every legal XML 1.0 Atom serialization; see the [Atom compatibility matrix](ATOM_RFC4287_COMPLIANCE.md).

EntityValue declaration processing shares the reference budget too, including numeric references in unused declarations. Repeated validation/application of a default pays for each pass; the budget is not reset or refunded between phases. Budget counters are deterministic algorithmic limits, not a claim of whole-process memory or wall-clock enforcement.
