# Atom RFC 4287 compatibility audit

MoonFeed's target is parsing and semantic handling for both RFC 4287 Atom Feed Documents and Atom Entry Documents. This audit describes the current implementation; it does not claim full RFC conformance. `PASS` applies only to the requirement as stated in that row, while `PARTIAL` means only the documented subset is implemented.

The normative references are [RFC 4287](https://www.rfc-editor.org/rfc/rfc4287) and [Namespaces in XML 1.0, Third Edition](https://www.w3.org/TR/xml-names/). RFC 4287 assigns Atom the namespace URI `http://www.w3.org/2005/Atom` and says the chosen prefix has no semantic significance. XML Namespaces defines an expanded name as a namespace name plus a local name, scopes declarations, gives default namespaces to unprefixed elements but not unprefixed attributes, and prohibits duplicate attributes by expanded name.

## Namespace equivalence evidence

`atom_test.mbt` parses two equivalent Feed Documents: one uses the default namespace, the other uses prefix `x`. The test compares title, updated value, author list, full entry values, entry ID, publication string, and normalized publication instant. `detect_test.mbt` also verifies that an arbitrary prefix and an Atom Entry Document root are recognized by namespace URI. Foreign `title` and `entry` elements with matching local names are ignored.

## Compatibility plan

1. Complete Atom Feed Document validation and add normative examples for field counts, ordering-independent parsing, person/category/link/content constraints, and duplicate elements.
2. Add `xml:base` URI resolution and complete `xml:lang` override/reset coverage.
3. Extend the public data model or add lossless Atom-specific metadata access for feed ID, contributors, person email, link metadata, category metadata, source, and foreign extensions.
4. Add standalone Entry Document parsing and define its mapping into the unified model.
5. Run external RFC-derived fixtures and security cases, then update this matrix only when corresponding implementation and tests pass.

Until those items are complete, MoonFeed claims namespace-correct Atom field matching and common Feed Document normalization, not full RFC 4287 compatibility.
