## A05：XML 实体处理

### 规范要求与安全边界

[RFC 4287 §2](https://www.rfc-editor.org/rfc/rfc4287#section-2)要求 Atom 文档是良构 XML，并未要求 DTD 有效性验证。XML 1.0 中与本次审计有关的要求如下；原文见 [XML 1.0 Fifth Edition](https://www.w3.org/TR/REC-xml/)。

| 条款 | 要求与边界 | 对本项目的判断 |
| --- | --- | --- |
| §§4.4.2、4.5、5.1 | 已读取内部声明产生的通用实体替换内容需要按上下文处理，包括内容中的标记 | 只支持文本替换不等于完整 XML；标记替换缺失是真实兼容缺口 |
| §2.8；§§4.4.8、5.1 | 非验证型处理器可不读取参数实体；若跳过，后续声明处理有规则，`standalone` 会影响这些规则 | 不必为关闭 PARTIAL 强行展开全部参数实体；整体拒绝属于更窄输入策略 |
| §2.8 的 PEs in Internal Subset | 内部子集的标记声明内部禁止参数实体引用，声明之间可以引用 | 不能把内部 `EntityValue` 中被禁止的 `%p;` 当作必须接受的合法案例 |
| §4.1 Entity Declared、No Recursion | 适用的实体须声明；属性默认值引用要求实体先声明；禁止递归 | 应区分使用时校验与声明时校验，以及 WFC 与有效性约束 |
| §4.2 的产生式 [72]、[74] | 参数实体定义不包含 `NDATA` | 接受这种声明是语法缺陷，不属于可省略的 DTD 实例验证 |
| §§4.4.3、5.1 | 非验证型可不加载外部实体，但应告知未读取的实体 | 禁止外部加载合理；不能静默伪造替换结果 |

规范没有规定“32 层、1,048,576 字符”这两个固定阈值。它们是实现的安全限制，不是 XML 合法性的定义；触发限制不意味着原文档必然不良构。也不能从允许不访问外部资源，推导出内部良构性检查可以省略。

### 当前实际实现

| 检查项 | 代码位置 | 实际行为与探针证据 |
| --- | --- | --- |
| 内部文本实体、引用时机 | `dtd.mbt:313`、`reader.mbt:491` | 声明时解析数字字符引用，保留通用实体引用到使用时；前向通用实体引用可解析，重复声明采用首次绑定。探针获得属性 `p="ok"`、文本 `ok < &` |
| 内部标记实体 | `reader.mbt:560` | 替换内容含字面 `<` 时返回 `Malformed("markup in a general entity is unsupported")`；`'<b/>'` 和 `'&#60;b/>'` 均拒绝；`'&lt;b/&gt;'` 正确成为文本 `<b/>`，不应误变成标签 |
| 参数实体 | `dtd.mbt:356`、`:532` | 声明可读但不保存；顶层 `%p;` 报 unsupported，不会继续按未读参数实体规则处理；内部声明中的 `%p;` 也拒绝，后者本来就受 §2.8 禁止 |
| 已使用的递归/未声明实体 | `reader.mbt:552` | 直接/间接循环均报 `recursive general entity`；`<x>&missing;</x>` 报 `unsupported entity` |
| 未使用声明的依赖 | `dtd.mbt:313`、`:427` | 未使用的 `&missing;`、未使用的循环声明不会全面检查；错误的属性默认值前向引用也被接受。不能仅凭使用时错误宣称内部子集所有 WFC 已覆盖 |
| 外部实体和资源 | `dtd.mbt:120`、`reader.mbt:579` | 外部标识符只解析，不访问；外部子集 URI 不加载，使用外部通用实体会报 unsupported。静态检查共享 reader 无文件/网络读取入口，探针使用不可用 URI 仍得到确定结果 |
| 展开限制 | `reader.mbt:24`、`:27`、`:491` | 路径深度最多 32 个实体；第 33 个被拒绝；每次解码累计输出字符限制为 1,048,576，没有全局展开次数/工作量计数 |

注意：现有范围文档用过“1 MiB per decoded value”的说法；代码实际计数为 `Char` 数量，应在后续修复文档时改为 **1,048,576 个字符/次解码**，不能当作整个文档的字节或内存上限。

### 确认的内部 DTD 误接受

以下小输入通过 Reader；将声明放入合法 Atom Entry 的 DOCTYPE 中，公开 `parse_atom_document` 同样返回正常 Entry，探针核对 `id == "urn:entry:1"` 和标题 `Entry`。

```xml
<!DOCTYPE x [<!ENTITY % p SYSTEM 'urn:p' NDATA n>]><x/>
```

参数实体不允许 `NDATA`。根因是 `entity_decl` 共享外部定义分支，没有依据 `parameter_entity` 限制该后缀。修复无需加载任何外部资源。

```xml
<!DOCTYPE x [<!ATTLIST x a CDATA '&later;'><!ENTITY later 'v'>]><x/>
```

属性默认值中的实体必须先声明；当前先收集完整实体表再应用默认值，未校验声明先后次序。另一个案例 `<!ATTLIST absent a CDATA '&missing;'>` 即使对应元素未出现，也不能以“不应用默认值”为由跳过其适用的内部子集 WFC。

未使用的循环声明也被接受。当前探针确认了该行为，不将其包装成完整声明图验证证据；后续处理应保留通用实体正常前向引用，按被读取实体和文档实体的相关约束区分诊断时机，不能笼统禁止一切前向引用。

### 新发现：输出上限不等于展开工作量上限

`decode_xml_value` 每次沿实体引用重新递归，没有缓存，也没有共享的调用次数/工作量预算。若叶子实体为空字符串，重复引用会使工作量增长，但 `output_chars` 始终为零，因此输出长度限制不起作用；不同名字的无环链也不会触发循环检测。

安全探针只使用 `e0=''`、每层引用前一层两次的 **12 层** 声明，断言最终为 `Text("")`。根据代码结构推算，32 个不同实体形成的允许深度理论上可产生约 `2^32 - 1` 次实体解码调用；**这是静态推导，没有运行该高消耗输入，也没有宣称测得实际耗时或内存值**。

建议在正式发布前补共享工作量预算，按引用/处理工作收费，覆盖空输出、属性、多个文本节点和整个文档；保留深度、输出上限和循环检测。缓存只能作为辅助手段，不能替代总预算，也不能忽略属性与文本上下文差异。测试应使用小的可注入预算验证提前失败，不靠运行攻击规模来证明安全。

当前未发现共享 XML reader 可触发外部文件或网络读取的路径；这不等于完成了所有安全性证明。上述 CPU 消耗风险与 XXE 是不同问题。

### A05 发布决策

- **应纳入 0.3.1 发布前的小修：** 工作量预算、参数实体 `NDATA` 语法拒绝、适用的属性默认值实体声明校验，以及具体错误/边界回归。
- **不建议塞入本次 patch：** 标记实体输入帧、完整参数实体处理机制或外部解析器；会扩大状态机及资源管理风险。若以后实现，仍必须禁止默认外部读取，并验证实体边界、替换上下文和预算。
- **可以合理保留 PARTIAL：** 明确披露安全子集和未支持的合法序列化。不得宣称完整 XML 1.0 / RFC 4287 兼容。现有误接受和工作量风险不能只靠 PARTIAL 标签掩盖。

## A20：MIME 注册类型与参数等价

### 规范范围

[RFC 4287 §§4.1.1–4.1.2](https://www.rfc-editor.org/rfc/rfc4287#section-4.1.1)限制相同 `type` / `hreflang` 的 alternate 组合；[§4.2.7.3](https://www.rfc-editor.org/rfc/rfc4287#section-4.2.7.3)中的 type 是媒体类型语法的提示值，不覆盖取得资源的真实类型。规范没有要求 MoonFeed 在运行时下载 IANA 注册表或实现所有 MIME 内容解码器。

[RFC 2045 §5.1](https://www.rfc-editor.org/rfc/rfc2045#section-5.1)规定类型、子类型、参数名大小写不敏感；参数值按对应定义决定，通常大小写敏感；引号不属于值。不能从“表示相同的内容”直接推导两个不同 type 属性在 Atom 组合约束中必然相同。

| 注册规则 | 规范依据 | 当前实现 |
| --- | --- | --- |
| charset 名称不区分大小写 | [RFC 2046 §4.1.2](https://www.rfc-editor.org/rfc/rfc2046#section-4.1.2) | 已处理；实现按参数名全局处理，未知私有类型同名参数也被折叠，缺少逐注册语义依据 |
| multipart boundary 值区分大小写 | [RFC 2046 §5.1.1](https://www.rfc-editor.org/rfc/rfc2046#section-5.1.1) | 正确保留 `AbC` 与 `abc` 差异 |
| message/external-body 的 access-type / permission / mode | [RFC 2046 §5.2.3](https://www.rfc-editor.org/rfc/rfc2046#section-5.2.3) | 已实现相应大小写例外；不执行外部取回 |
| application/atom+xml 的 type=entry/feed | [RFC 5023 §12.1](https://www.rfc-editor.org/rfc/rfc5023#section-12.1) | 大小写等价；entry 与 feed 不混淆。引用此注册补充不代表实现 AtomPub |
| text/plain 的 Format / DelSp 及默认行为 | [RFC 3676 §4](https://www.rfc-editor.org/rfc/rfc3676#section-4) | 大小写已实现；未做省略/未知值的默认语义归一化。前一份维护审计写成 §3，应以本报告的 §4 为准 |
| multipart/related 的 type 是根部件媒体类型 | [RFC 2387 §§3.1、3.4](https://www.rfc-editor.org/rfc/rfc2387#section-3.1)，[IANA 注册记录](https://www.iana.org/assignments/media-types/multipart/related) | 将内嵌类型当普通大小写敏感字符串；由该注册定义结合 RFC 2045 推导，应比较其中类型/子类型的大小写等价 |

### 当前算法与独立探针

位置：`src/atom/media.mbt:57` 的 `parse_media_type`、`:137` 的 `same_media_type`；公开文档 API 由 `document.mbt:201` 的 `strict_links` 调用。

| 输入对/行为 | 实际结果 | 审计判断 |
| --- | --- | --- |
| `Application/X-A;x=One;y=two` / `application/x-a;Y=two;X="One"` | 相同 | 通用名字、引号和参数次序规则有证据 |
| 不同未知 essence，或未知参数 `One` / `one`，或缺失/出现未知参数 | 不同 | 没有把所有未知类型/参数合并 |
| 同名未知类型及完全匹配的参数值 | 可相同 | 仅依据通用语法比较，不声称了解其私有语义；未知不意味着永远不能相同 |
| `x=a;x=b` / `x=b;x=a` | 相同 | 作为多重集保留出现次数；没有 Map 的覆盖丢失 |
| `x=a;x=b` / `x=a;x=a` | 不同 | 没有抹除重复值差异 |
| `application/atom+xml;type=ENTRY` / 同类型 `type=entry` | 相同；公开 API 拒绝重复 alternate | 正确的已注册参数规则；错误路径为 `entry.link[1]` |
| `multipart/related;boundary=b;type="Text/HTML"` / 同类型 `type="text/html"` | 不同；公开 API 接受两个 alternate | 具体注册规则遗漏，不只是“可能还有未知类型”。内嵌 type/subtype 大小写应等价 |
| `text/plain` / `text/plain;format=fixed` | 不同 | 未应用 RFC 3676 的处理默认；不能单凭渲染默认就宣称 Atom 必须将两个显式属性合并 |
| `text/plain;format=flowed` / 增加 `delsp=no` | 不同 | 同上，区分媒体处理默认与 Atom 属性等价的规范推导 |
| 同一 type 内 `charset=utf-8;charset=us-ascii` 及倒序 | 语法接受、作为同一多重集 | 没有注册特定的冲突参数政策；不能猜测 first-wins / last-wins |
| 私有 `application/x-a;charset=AbC` / `charset=abc` | 相同 | 全局 charset 特例的实际边界；不能宣称“所有未知参数均按原大小写” |

当前还不实施通用 charset 别名、各类型特有数值/枚举值、缺省值和重复约束的完整语义库。通用 RFC 2045 参数产生式允许重复出现的形式，并不能据此证明某个注册类型的冲突参数有效；也不能反向发明“所有 MIME 参数重复一律非法”的 Atom 规则。对没有明确规则的情况，应保留原值并披露确定的比较政策。

### A20 发布决策

- **值得纳入 0.3.1 的有限修复：** 处理已确认的 `multipart/related` 内嵌类型大小写规则；为未知类型/参数及重复冲突明确比较边界，避免仅靠同名参数套用未经证实的注册语义。增加注册特例时应精确限定类型与参数，保留 boundary、profile 等负向用例。
- **不建议为 patch 扩展：** 自动抓取整个注册表、将所有默认值/别名视为等价、无依据丢弃未知参数或全局禁止重复参数。默认媒体处理行为不自动构成 Atom alternate 属性等价；注册中未定义的重复冲突不能猜测。
- **可以合理保留 PARTIAL：** 有限注册规则的范围可清晰披露。已有通用语法与若干注册规则不构成任意 MIME 注册语义的完整证明。该项不是要求实现所有已注册类型的下载、渲染或内容验证。
